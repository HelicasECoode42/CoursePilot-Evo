# 内部 PRD v0.2｜CoursePilot-Evo（五周范围）

状态：待开发。目标用户是选择培养路径并希望核对学业要求的学生；教师查看可解释结果与工程实现。需求以真实 `.xls` 及[字段核查](06-workbook-audit.md)为边界。

## 核心体验

**展示层确定为响应式 Web 前端：Vue 3 + Vite。** 首版不做微信小程序。网页只有一个主工作台：左侧选择培养路径、录入已修课程与自然语言目标；右侧显示要求缺口、建议课程、依据和未知事项；底部可展开工具调用/核验记录。手机浏览器可用，但不做原生 App。

用户路径：选择已核实的路径 → 输入课程代码/学分或上传模板 → 提问 → Agent 查 Java 工具 → 返回“已满足/还缺/未知”及课程建议 → 用户修改偏好再问。每条规则结论要能定位到教学计划的工作表和行。若用户说“周五空出来”，系统说明当前仅有培养计划，没有班次时间，并询问是否提供班次快照；不能直接排出周五空课的课表。

## P0 / P1 / 非目标

| 级别 | 功能 | 验收 |
| --- | --- | --- |
| P0 | 选择 2024 级培养路径，导入并核对一条经确认的路径 | 显示文件 hash、路径和来源行；异常课程不能静默丢弃 |
| P0 | 已修记录与培养要求核对 | 已知项给出学分/规则依据；缺数据返回未知 |
| P0 | Planning Agent 调查与建议 | Tool Trace 可见；最终硬事实均由 Java 结果支持 |
| P0 | 响应式单页 | 一次演示能完成录入、提问、核验、修改目标 |
| P1 | 固定 Benchmark 和 Trace | 每个 case 有标准、输入版本、输出、错误与耗时 |
| P1 | 最小自进化闭环 | 自动提出至少一个 Prompt/Tool 描述候选；复评后晋级或回滚留记录 |
| 非目标 | 实时选课、抢课、学期班次冲突、周五空课保证、小程序 | 有独立班次数据才重新评估 |

## 页面状态与文案

- `已核验`：Java 返回的确定性事实，显示来源。
- `建议`：Agent 的取舍判断，写明参考事实和用户偏好。
- `未知`：培养表没有或需人工确认的数据；不能渲染成绿色通过。
- `系统错误`：服务/模型失败，与业务未知区分；保留输入，允许用户重试。

第一版不做复杂课表日历、社交、登录系统。演示可使用本地匿名会话和虚构/经授权的已修记录。真正接入学生成绩前再做账号、隐私和权限设计。

## 验收指标

见[Benchmark 协议](07-benchmark-protocol.md)。不预填准确率或提升幅度；报告同时展示失败样例和模型调用成本。
