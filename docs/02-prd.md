# 内部 PRD v0.1｜CoursePilot-Evo

状态：待团队确认；没有功能实现或用户研究结果。目标用户为需要核对培养要求并规划下一学期课程的学生；教师是项目评审者，不是选课决策者。

## 用户问题与价值

学生往往同时面对培养方案规则、已修记录、开课班次和“周五空课”等偏好。系统应让学生看到**哪些是已核验事实、哪些是主观建议、哪些信息未知**，并能针对不满意的方案继续对话。

## 首版使用路径

1. 用户选择培养方案与学期快照，导入/输入已修记录；页面显示学期、来源、更新时间和缺失字段。
2. 用户写自然语言目标；Agent 提取必选条件与偏好，歧义会影响结果时才澄清。
3. Agent 调 Java 工具查询要求缺口、课程和班次，提出至多 3 个候选方案。
4. Java Verifier 检查每个方案的课程存在性、学分与培养规则、班次冲突、用户硬条件；给出结构化问题与来源。
5. Agent 修正一次或请求用户放宽条件；展示有依据的方案、取舍、未知项和下一步。
6. 用户修改偏好后再规划；保留前后差异与验证记录。

## 需求优先级

| 级别 | 需求 | 验收方式 |
| --- | --- | --- |
| P0 | 数据版本与来源可见 | 每项确定性结论能指回规则或快照 |
| P0 | Java 查课、要求核对、冲突与方案核验 | 固定样例与人工标准一致，未知项不假判通过 |
| P0 | Agent 只通过工具获取硬事实并能处理核验失败 | Trace 可看到调用、错误、修正与最终结论 |
| P0 | 固定 Benchmark 与 Trace | 同一数据版本下可重放输入和评分 |
| P1 | 受控 Harness 自进化一次完整循环 | 候选修改、留出集复评、晋级或回滚记录齐全 |
| P1 | 简洁页面展示方案与来源 | 教师演示可走通完整路径 |
| P2 | 多方案优化求解、实时校内接口、个性化排序 | 数据和时间允许时才进入计划 |

## 明确边界

- 不自动选课、不承诺本期余量或教师评价准确。
- 小本本的主观评价只作带出处的参考文本，不进入客观硬规则。
- Harness 首版只允许修改提示词、Skill 文本或工具说明，不允许修改 Java 规则、评分器、训练/留出任务答案、模型配置与预算。
- 没有可靠班次快照时，不展示可行课表判定；交付范围按教师版第 1 周门槛收缩。

## 关键产品指标（待实测）

核心：核验后的硬约束违规数、培养要求核对正确率、数据未知项识别率、证据覆盖率、完整任务成功率。辅助：用户完成一次规划的轮数、P95 耗时、模型调用和 token 成本。自进化看训练集改善与留出集回归，两者必须同时报告，绝不只展示“最佳样例”。
