# CoursePilot-Evo：课程项目方案摘要

本文面向项目介绍与课程汇报，描述设计目标，尚未宣称服务、真实班次接入或实验指标已实现。开发团队从[业务总览](15-team-baseline-and-batches.md)进入，完整需求见[PRD](02-prd.md)，实际排期见[第五至第八周安排](19-delivery-plan.md)。

## 项目解决的问题

学生选课需要同时考虑培养要求、已修进度、兴趣、教师反馈、工作量、签到与时间。项目拟用一次一问的网页帮助学生表达组合目标，查询有来源的资料，核对要求、比较候选并修改条件。职业发展是可选分支，实际选课由学生在官方系统完成。

首版以一个计算机培养路径为范围。教学计划含课程/学分/建议学期与文字规则，不含班次时间，数据依据见[工作簿核查](06-workbook-audit.md)。真实选课页不可实测，班次适配仍是设计；模拟班次只验证时间算法。有限评价保留课程/教师/学期与来源，历史主观反馈不能证明当期开课或保证高分。

## 两条交付主线

学生线：资料 → 学业核对 → 表达目标 → 比较课程教师 → 生成并核验推荐 → 澄清/取舍 → 改条件重规划。

实验线：独立案例 → 同一 Agent 基线 → 质量/成本/失败 → 跨案例假设 → 受限策略修改 → 隔离评测 → 保留/回滚及报告。至少实际执行两轮候选决策，拒绝分支也保存。节省 Token 与质量提升是待实测假设。

## 技术与分工

Java/Spring Boot/MySQL 保存事实并计算学分、时间与合法性；Python/LLM 理解需求和解释候选；Vue 页面完成学生流程及独立老师报告。A 数据输入、B Java 核验、C Agent、D 评测改进、E 网页的完整职责见[模块说明](05-team-and-sub-trds.md)。评测与学生使用相同 Agent；策略改进限定白名单，不自动修改 Java、答案或评分标准。

## 验收与限制

交付应包含可运行学生演示、来源/未知清晰表达、普通与异常回归、四组逐例评分、固定运行条件、Token/耗时覆盖率和候选版本关系。题集目标四组各 5+5，最低各 3+3并说明局限；完整评分与晋级门槛见[协议](07-benchmark-protocol.md)。

没有真实班次时保留课程层规划和时间未知，另展示显著标记的模拟冲突。首版不做学校登录代管、自动选课、小程序、全校专业或实时爬虫。报告区分设计、实际实现、模拟输入和实验结果。

设计参考：[GDPevo](https://github.com/Prism-Shadow/GDPevo) 的任务组思路与[PhysicalRSI](https://mmlab.hk/research/PhysicalRSI) 的分层/经验固化方向；不声称复现其系统或结果。
