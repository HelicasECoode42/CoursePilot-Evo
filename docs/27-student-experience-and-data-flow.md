# 学生页面、接口与数据流转

## 产品目标与实现分工

学生导入学校学业情况，查看学分进度，通过完整引导表达下学期目标，选择课程并理解推荐依据，再调整方案和课表。学分计算、评价来源、方案编辑和时间核验需要对应到保存的数据。

Luna 负责本轮前端代码、导入连接修正和相关测试；主 Agent 负责业务与接口文档、实现审核和验收。已有未提交修改保留。每轮实现结束后安排一名 Luna 独立检查，主 Agent 根据检查结果验收。

## 页面与操作

| 页面 | 学生操作 | 数据与后续页面 |
| --- | --- | --- |
| 首页 `/` | 了解流程，点击开始规划 | 进入 `/setup`；已有会话仍使用当前资料 |
| 连接 `/setup` | 查看扩展安装说明，连接学业资料 | 准备会话并进入 `/records?import=school`；准备失败留在当前页重试 |
| 学业资料 `/records` | 选择培养方案，连接扩展，前往学校页面主动读取并导入；也可选择已有 JSON | 保存成功后显示本会话记录；手动补录作为另一种输入方式 |
| 我的学业 `/me` | 查看学分进度、搜索课程与评价、了解方向 | 学校进度、课程目录、评价分别读取；自由问题进入原有引导 |
| 逐步引导 `/plan/questions/*` | 表达目标、考核偏好、兴趣与发展方向、课程教师意愿、时间与优先级 | 保存在规划草稿中；返回修改保留已填内容；资料确认后提交规划 |
| 课程选择 `/plan/credits` | 查看类别缺口和候选，勾选课程、查看已选学分 | 选择进入规划草稿；未知学分不纳入凑分计算 |
| 结果 `/plan/result` | 查看课程、理由、评价依据、核验结果，删除或更换班次 | 调用确定性编辑接口生成新方案版本，并同步当前展示；有目标学期班次时展示课表 |

引导保留独立 HTML 的目标组合、目标排序、给分反馈、签到、作业、小组任务、展示、考试偏好、兴趣、职业与科研探索、课程教师 MUST/PREFER、必须与尽量避开的时间。所有学生均能看到各问题，不能按动机隐藏问题。设计要求允许留空跳过；现有 Vue 的目标题仍要求至少选择一个目标，`advance()` 和 `firstIncompleteQuestion()` 均限制空目标继续。此项需要后续统一页面、请求构建与契约行为。

页面采用一致的浅绿色、圆角卡片、正文宽度和按钮层级。学业概览分别显示学分、课程、方向，避免同时展开全部资料。流程状态参考 [GOV.UK 多任务模式](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)，自由输入与后续整理参考 [Todoist 功能展示](https://www.todoist.com/features)。引用用于交互研究，页面样式由项目自行实现。

## 技术栈与责任

| 部分 | 技术栈 | 责任 |
| --- | --- | --- |
| 学生网页 | Vue 3、TypeScript、Pinia、Vue Router、Vite | 展示事实，保存当前会话草稿，发起接口调用；不复制 Java 的学分和时间算法 |
| 学校读取扩展 | Chromium Manifest V3、content script、service worker、DOM | 读取学生已登录的学业情况页面，保留类别树、课程和状态，送回发起标签页 |
| API 与 Agent | Python、FastAPI、Pydantic、typed ToolClient | 验证会话、转发 Java 查询；Planning Runner 使用事实和评价生成理由与方案 |
| 事实与核验 | Java、Spring Boot、Spring Data JPA、H2 | 保存学校快照与学业记录，查询课程和评价，计算本地核对，解析时间并核验方案 |

Web 仅调用 Python API，Python 通过 typed HTTP 调用 Java；Java 不调用模型。开发代理将 Web `/api` 转发到配置的 Python 地址，模型密钥保留在后端。

## 学校导入与学分展示

1. CoursePilot 创建会话并选择培养方案。学生主动点击连接后，扩展登记发起标签页和 `requestId`。
2. 学生在上海大学学业情况查询页面登录、展开需要读取的内容，点击浮窗导入。扩展发送类别节点和课程明细，不发送学校登录凭据。
3. App 级接收器在各路由持续监听。消息必须来自本窗口、同源，并匹配等待中的请求号；同一导入保存期间重复投递复用保存结果。
4. `PUT /api/v1/school-progress` 携带当前会话身份、`X-Request-Id` 和 `Idempotency-Key`。Python 派生 subject 并调用 Java；Java 在事务中保存学校快照及映射的学业记录。
5. Java 用培养快照与内容摘要复用相同导入。课程尝试按课程号和修读学期去重；冲突记录保留 UNKNOWN。在读课程不计作已获学分。
6. 只有后端保存成功才回复成功回执；失败显示原因并允许重试。扩展返回发起页面，随后可进入我的学业查看进度。

学校报告与本地核对分别展示：

| 数据 | 来源 | 展示规则 |
| --- | --- | --- |
| 要求、已获与剩余学分 | 学校学业情况节点 | 原值展示；缺失显示待确认；不累加父子节点得出总数 |
| 类别层级 | 节点 ID 与 parentId | 同名父子节点保留，按 ID 关联；子类别可展开 |
| 本地核对的 SATISFIED / UNSATISFIED / UNKNOWN | Java Audit | 单独显示来源和无法确认原因，不被学校汇总覆盖 |
| 已修、挂科、在读等课程状态 | 导入课程明细 | 用于记录与候选处理；只有已通过记录支持排除已修课程 |

`SchoolProgressService` 当前把映射记录的 `transcriptComplete` 设为 `false`。仅凭页面汇总不能证明每条课程明细均已读取，因此本轮不直接改为完整记录。默认进度展示读取学校报告的剩余学分，本地核对继续保留 UNKNOWN。完整性判定需要与实际展开读取覆盖范围一起验收。

## 课程、评价与推荐

课程目录按培养快照读取全部分页，支持课程名与课程号搜索。不同类别中的同一课程可以保留多条类别记录，课程数量按唯一课程号统计。目录中的建议学期不代表目标学期开课。

评价通过 `GET /api/v1/reviews/search` 分页读取，按课程和维度展示记录数量及原文依据。一条记录可涉及多个维度，记录数不等于独立人数。课程层评价不归到未确认的教师；暂无评价、查询失败、来源未确认分别呈现。

方向资料仅在学生展开时查询；学生点击选择后才加入原有自由输入。样例方向保留资料标记。方向介绍与模型生成的学习步骤不能标为学校发布的课程事实。

自由问题、兴趣与方向、偏好、优先级、已选课程和课程教师意愿经过现有规划请求构建器进入 Runner。Runner 从 Java 查询课程、学业核对和评价，生成逐课程理由。引用评价必须来自同课程的查询结果。Java 返回核验结论，前端展示实际结论；缺失班次时保留课程建议和时间未知状态。

## 删除、换班与课表

删除调用 `POST /api/v1/session-plans/remove-course`，输入当前方案和课程号。Python 检查会话归属，移除课程及其固定约束，保留其他项；剩余方案交 Java 重新核验后保存新版本。最后一门删除后保存空方案，核验结果为 null。前端同步新版本，不能仅隐藏卡片。

换班沿用方案替换接口，选定班次后重新核验整份方案。Java 从原始排课文本统一解析时间。下学期课表需要目标学期开课快照；当前在读课程不作为下学期冲突来源。没有已核验真实班次时，真实课表验收仍需相应数据。

## 学业资料与学分选课的接口衔接

本次前端修改范围为 `/records` 与 `/plan/credits`。其他页面保持既有布局；AI 对话仅确定处理方案，不在这轮增加对话入口或付费调用。

| 操作 | 接口或状态 | 消费方式 |
| --- | --- | --- |
| 建立会话 | `POST /api/v1/sessions` | HTTP client 保留令牌；后续请求使用同一会话 |
| 选择培养方案 | `GET /api/v1/curriculum-snapshots` | 保存 selectedCurriculumId；切换方案使旧核对和已选项失效 |
| 读取或更新学校进度 | `GET /api/v1/school-progress`、`PUT /api/v1/school-progress` | 返回 receipt、snapshot、academicRecord；分类和课程关系读取 nodeId、parentId |
| 读取学业记录 | `GET /api/v1/academic-records` | 返回本会话记录；选定记录用于核对，已通过课程用于候选排除 |
| 本地核对 | `POST /api/v1/requirements/audit` | 输入培养方案与记录 ID，返回 requirementId、category、缺口和三态；保留 UNKNOWN |
| 读取课程 | `GET /api/v1/courses` | 携带培养快照 ID，按 cursor 读取目录；类别、学分与建议学期均取服务端值 |
| 选课与移除 | Pinia draft.selectedCourseCodes | 页面间沿用；按唯一课程号展示已选清单，局部选择不直接写入已修记录 |
| 最终生成方案 | `POST /api/v1/planning` | 请求构建器将已选课程转为 PIN_COURSE，并带记录 ID、目标、偏好和自由输入 |

导入成功只表示学校快照和映射记录已保存。没有本地核对结果时，页面应仍能展示学校类别进度，提供核对操作；课程建议不能自行变成已获学分。

学校类别与培养要求没有共享的分类 ID。学校 parentId 表示层级，不能用缩进代替关联；同名节点不能合并。唯一名称匹配可用于标注对应的学校报告参考值，但不能据此改变 AuditItem 或宣称已确认学分抵扣。抵扣关系、跨类别计分和毕业结论由 Java 负责。前端仅对已选课程已知学分求和，学校剩余学分与本地核对缺口分别标明来源。

## 用户画像、AI 对话与规则职责

当前实现只有会话草稿和事实引用，尚无跨会话用户画像服务。规划时，Runner 先读取 Java 学业核对与课程、评价，再生成建议；填写兴趣文本或读取学业记录本身不触发模型。

接口核对还发现两项需要后续统一：Runner 当前直接使用 AcademicRecord 和 AuditResult，没有读取完整学校进度树，不能宣称学校报告缺口已全部进入模型；Runner 的 taken_course_codes 排除所有非 FAILED 状态，而学分页面按 PASSED 排除已修，IN_PROGRESS 和 UNKNOWN 的候选处理存在差异。此轮只改两页，不将这两项后端行为描述为已修复。正式个性化推荐验收需覆盖这两个输入路径。

画像设计采用以下字段分工：

| 内容 | 数据与确认方式 | 使用规则 |
| --- | --- | --- |
| 学业事实 | 培养快照 ID、学校进度快照 ID、学业记录 ID、导入时间与来源 | 引用事实版本，不复制成可由模型修改的成绩或学分 |
| 明确偏好 | 当前 motives、priorityOrder、classPreferences、teacherPicks、mustSlots、preferSlots | 保存学生的选择；硬条件与软偏好区分；学生可以修改 |
| 兴趣与方向 | 原文 careerText、interestTags、自由问题 | 保留原文；“考虑人工智能”不能自动变成“必须选人工智能课” |
| AI 推断 | 建议的兴趣、方向和需澄清事项 | 显示待确认；只有学生明确采用才写回偏好，不修改学校事实 |
| 课程选择 | selectedCourseCodes、方案 ID 与编辑版本 | 显式加入/移除后更新；聊天提到某门课不自动加入方案 |

后续对话应按“输入问题 → 读取必要事实 → 解释或追问 → 展示可采用的偏好修改 → 学生确认 → 更新草稿”处理。探索职业与科研方向不要求学生先填完整成绩；缺少个性化事实时，仍可讨论方向，并明确哪些建议尚未结合学业进度。

对话与正式规划复用现有模型适配器、预算和事实查询服务。正式方案继续经唯一 Planning Runner 与 Java 核验。新增对话接口需要单独确定请求与响应契约，不能在现有规划接口仍要求 academicRecordId 时绕过其输入要求。对话状态应区分处理中、成功、澄清、失败；失败保留原草稿，避免每次输入自动调用模型。

模型只接收当前问题所需的课程、类别缺口、相关评价和偏好。学校凭据、完整原始成绩单和无关个人字段不进入对话请求；评价文本作为引用资料处理。长对话摘要不能覆盖已确认的事实和硬条件。

| 职责 | 处理方式 |
| --- | --- |
| 学分、已修去重、课程与班次存在性、时间冲突、对象归属 | 确定性规则和服务端事实；结果可复核 |
| 类别抵扣与毕业要求 | Java 已建模规则；未建模部分保留未知，不由模型补写结论 |
| 理解自由表达、识别取舍、解释评价、提出探索方向与学习步骤 | AI 结合事实提出建议，推断需确认 |
| 恰好补足、最少超出和候选排序 | 保留确定性组合算法；名称关键词匹配仅标为关键词排序，不能称为语义理解 |
| 偏好改变与选课操作 | 学生明确确认；删除和换班走既有确定性编辑接口 |

规则不负责替学生判定兴趣、自动要求高绩点或推断职业目标。AI 不负责更改已修课程、计算毕业结论或把未知班次描述为无冲突。验收分别检查事实准确、偏好表达忠实、建议有依据、修改可追踪，不能只以接口返回成功评价对话质量。

候选筛选需要按任务确定：补专业选修学分时以该类别未修课程为候选；学生明确要补修或重修基础课时，允许按相应任务讨论。不能因为培养计划建议大一修读，就推断学生已经通过，也不能把“少作业”等软偏好变成排除所有缺评价课程的硬规则。缺评价课程仍可按课程事实讨论，但没有依据的给分、考勤和工作量结论不能生成。

## 与本轮相关的安全要求

- 扩展连接只接受支持的本机来源和顶层标签页。重复连接应允许原标签页恢复，其他标签页不能覆盖有效接收目标。
- 保存结果由后端确认；消息来源、请求号与会话归属分别处理，前端收到消息不直接构成保存成功。
- 学校快照、学业记录和方案按当前会话身份读取，浏览器不指定其他用户的 subject。
- 课程、评价和模型文本通过文本插值展示；不执行其中的脚本或指令。
- 真实来源、未核验来源与合成样例维持原标签。切换前端布局不能改变来源资格。
