# 课表人工核验指南

这份指南写给**负责核验的队友**。核验人不能是上传课表的人。

## 为什么要核验

系统里的本学期课表，是从学校公布的《26-27 学年秋季学期本科生课程表》PDF 转换来的。转换由程序完成，可能读错列、截断时间、把老师和容量粘在一起。项目规定：上传者自己说"没问题"不算数，必须由另一个人抽查确认后，课表才能标成"已核验"。核验之前，结果页会照实显示"班次来源尚未核验"。

## 你需要的东西

- 原始 PDF：`data/raw/2026-11-school/附件3-26-27学年秋季学期本科生课程表.pdf`（只在负责人电脑上，不在 git 里，需要向负责人要）
- 抽样表：`data/private/offerings/verification-sample.csv`，固定随机抽出的 50 行，按页分层抽样，每行带 PDF 页码

## 怎么核对

对抽样表的每一行：

1. 打开 PDF，翻到这一行写的页码。
2. 找到同一个课程代码和教学班。
3. 逐项对照：课程代码、课程名、学分、教师姓名、容量、上课时间（星期、节次、周次，包括单双周）、校区。
4. 有任何一项不一致，就在这一行的"核验结果"列写"错"，并写清哪一项、PDF 上的原文是什么；全部一致写"对"。

注意：

- **上课时间要逐字对照**。"1-16周(单)"和"1-16周"是不同的。
- PDF 上本来就没写时间的，系统里也应该是空的，这种算"对"。
- 不要在 CSV 里改数据本身，只在结果列里记录。

## 判定标准

- 50 条里错 1 条及以下（≤ 2%）：通过。
- 超过 2%：不通过。把错误发给负责人修转换脚本，修好后重新抽样、重新核验。

## 核验完成后

把下面这些发给负责人，由负责人用管理员密钥录入系统：

- 核验人姓名
- 上传者姓名（必须和核验人不同，否则系统拒绝）
- 抽样条数和错误条数
- 填好的 CSV 文件（系统会记下它的 SHA-256，作为核验留档）
- 一句备注，比如"对照 PDF 第 x～y 页抽查 50 条"

录入接口是 `POST /api/v1/offering-snapshots/{snapshotId}/verification`。系统会记录核验人、时间和抽样统计。核验通过后，这份课表在结果页会显示为"已核验"。模拟数据不能走这个流程。

## 核验不代表什么

核验只说明"系统里的数据和学校 PDF 一致"，不保证学校之后不会调课。学校发布新版课表后，要重新导入、重新核验。
