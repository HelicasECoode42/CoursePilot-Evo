# 用户画像、项目流程与接口对照（2026-10-30）

依据：`docs/26`、`docs/27`，以及 Haiku 对三层接口的代码对照和本机实测。

## 1. "用户画像"指什么

不是一个单独的服务，而是**规划时用来描述这个学生的一组数据**，分五块（定义见 `docs/27`「用户画像、AI 对话与规则职责」）：

| 块 | 内容 | 谁来改 |
|---|---|---|
| 学业事实 | 培养方案、学校进度快照、学业记录（只存 ID 引用） | 只能靠导入，模型不能改 |
| 明确偏好 | 目标与排序、上课偏好、教师意愿、必须/尽量避开的时间 | 学生在逐步引导里填 |
| 兴趣与方向 | 职业/兴趣原文、兴趣标签、自由提问 | 学生原话，"考虑 AI"不等于"必须选 AI 课" |
| AI 推断 | AI 建议的兴趣、方向、需要澄清的点 | 应先显示为"待确认"，学生点了才写入 |
| 课程选择 | 已选课程、优先考虑的课程、方案版本 | 学生显式加入/移除 |

现状：前四块的数据都在**当前会话的草稿**里，**刷新或换会话就没了**，没有跨会话保存。"AI 推断待确认"这一步还没做，现在是点一下就直接写进去。兴趣标签页面上没地方填。

## 2. 项目流程（学生视角）

1. **首页 `/`** → 开始规划。
2. **连接 `/setup`** → 建会话。
3. **学业资料 `/records`** → 选培养方案；用浏览器插件到学校正方系统读取学业情况并导入，或手动上传 JSON。
4. **我的学业 `/me`** → 看学分进度、搜课程和评价、看方向；**AI 问答**在这里。
5. **逐步引导 `/plan/questions/*`** → 一次一问，所有问题都能跳过：目标、考核偏好、兴趣方向、教师意愿、时间、优先级，最后到确认页。
6. **学分选课 `/plan/credits`** → 按类别缺口勾课程。
7. **结果 `/plan/result`** → AI 给出方案和逐课程理由，Java 核验冲突；可以删课或换班，换完重新核验；有下学期班次数据时显示课表。

数据走向固定为：**网页 → Python → Java**。模型只由 Python 调用，Java 只管事实和核验。

## 3. 接口能不能对上

**结论：能对上。** 本机三个服务都在跑，实测也通过。

| 层 | 结果 |
|---|---|
| 网页 ↔ Python | 合同共 20 个接口，Python 20 个全都实现了，网页用了 19 个，没有路径对不上；字段逐项比对一致 |
| Python ↔ Java | Python 调用 Java 的 14 个接口，在 Java 合同和代码里都有，实测能通 |
| 合同检查 | `check_contracts.py`、`self_check.py` PASS；接口合同相关测试 54 项通过 |

小问题（都不影响现在使用）：

- Java 合同里写了两个接口，代码里却没有：`POST /api/v1/preferences/score`（实测 404）、`POST /api/v1/offering-snapshots/import`（实测 400）。目前没人调用，要么补上要么从合同里删掉。
- Java 有 3 个接口合同里没写：`/api/v1/verification/credit-gap`、`parse-time`、`conflicts`，也没人调用。
- 合同里 `ImportWorkbook.sourceKind` 字段，Python 那边没有（`agent-runtime/src/agent_runtime/api/schemas/manifest.py:65`）。
- `agent-runtime/src/agent_runtime/api/routes/plan_replacement.py:3-4` 的注释说这两条路径在 planning 合同里，其实它们在 Java 合同里。
- `java-environment/src/main/resources/application.properties` 里的默认服务密钥和本机实际运行用的不一样，新人照默认值启动 Python 调 Java 会拿到 401。

未验证：Java 的 `mvn test` 没跑；Java 的数据结构是抽查，不是逐个比对。

## 4. 已知后端缺口（来自 docs/27）

- 规划 Runner 只读学业记录和本地核对，**没读完整的学校进度树**，所以不能说学校报告里的缺口都进了模型。
- "已修"的判断不一致：Runner 把除"挂科"以外的都当已修，学分页只把"通过"当已修，"在读"和"未知"的课在两边处理不一样。
