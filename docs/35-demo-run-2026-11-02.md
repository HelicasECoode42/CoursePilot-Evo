## 结果页的四条"无法确认"（用户录屏复核后更正）

前面把"生成方案"记成了通过，这是错的。结果页的核验结论有四条"无法确认"，等于核验这一步没有完成。逐条原因如下：

| 文案 | 触发位置 | 真实原因 | 性质 | 要怎样才能"能确认" |
|---|---|---|---|---|
| 有一项课程或班次信息无法确认 | `ResultView.vue:198-200` 的兜底文案 | 前端拿到的原因码在映射表里查不到。多半是在读课程（`PENDING_COURSE`），一次 8 门被合并成一行，也没写出是哪几门。另外 Java 发出的原因码是 `UNMODELED_CURRICULUM_RULES`，前端映射里写的是 `UNMODELED_RULE`，所以"未建模规则"的说明永远显示不出来 | **bug** 加文案缺失 | 修正映射的键名；给在读课程等情况补上文案，并列出具体课程 |
| 班次来源尚未核验，无法确认实际上课时间 | `PlanValidationService.java:205-210` | 系统里只有一个班次快照，是合成数据（2025 秋），**下学期的真实开课资料一份也没有**；代码里也没有任何生产路径能把班次标成"已核验" | 设计如此，缺数据和流程 | 拿到下学期真实开课资料，并补上人工核验流程（核验人、审计记录）。AGENTS 规定上传者自报的来源不能自动算核验 |
| 部分限制条件缺少核验所需资料 | `PlanValidationService.java:233-255` | 学生设了时间方面的硬条件，但没有可用的班次时间 | 设计如此，跟上一条同源 | 同上 |
| 已修课程可能未填全 | `AuditResultAssembler.java:121-124` | `transcriptComplete=false`。学校导入时写死为 false（docs/27 定的），只有学业资料页的"记录已完整"勾选框能改成 true | 设计如此，但学生不知道该做什么 | 导入后明确提示学生核对，然后勾选"记录已完整"；如果要让导入自动算完整，需要另改合同 |

另外，结果卡片上的"未查询评价"不是数据错误：规划时默认只查前 2 门课的评价，AI 问答则是单独查询的。文案应改成"本次规划未查询"，或者调高查询配额。

**验收口径**：只有数据齐全（核验过的目标学期班次、完整的学业记录）、并且核验结论里没有"无法确认"时，才算核验通过。仅凭接口返回 200 不算。

## 其他问题

1. **刷新页面或重新打开浏览器，会话和学业记录就没了**。这是演示风险最大的一条。站内跳转不受影响。
2. 仓库里没有学校进度 JSON 的合成样例，所以"选择已有 JSON"这个入口没法演示。
3. 规划结果里的课程卡片写着"未查询评价"，但 AI 问答在回答同一门课时引用了评价，两边说法对不上。
4. Cloudflare 自动注入的统计脚本被 CSP 拦下了。不影响功能。
