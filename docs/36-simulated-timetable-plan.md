## 方案

1. **生成模拟课表（只做计科）**：从教学计划里取本学期该开的课，每门课开 2～3 个班。
   - 每周上几次 = 学分 ÷ 2，向上取整；每次 2 节。例如 6 学分就是一、三、五各上第 1-2 节。
   - 同一门课的不同班错开时间；有一部分班上单周或双周，好让冲突检查有东西可查。
   - 班次的老师用评价里出现过的"教过这门课的老师"，这样评价能按老师展示。所有班次都标 `SYNTHETIC`，`meetingTextRaw` 用 TimeParser 认得的写法（例如 `星期三第3-4节{1-16周(单)}`）。
   - 生成脚本放进仓库；生成出来的数据放在 `data/private`，不进公开仓库，因为里面有真实老师的名字。
2. **Java**：实现班次导入接口（需要管理员密钥），班次要关联到所属的快照。
3. **评价**：按 `||` 拆成单条重新导入；从评价里的老师名生成"老师-课程"绑定，评价改成按老师加课程汇总展示。拆分之前要先对照原始 PDF，确认 `||` 确实是分隔符。
4. **通识课**：不列具体课程，只显示学校报告里每一类"还差多少分"。
5. **加课推荐（新功能，取代拖拽）**：根据当前已选的课和剩余学分，找出空闲时段，推荐跟已选课不冲突的班次，按评价排序；点一下就加进方案，由 Java 重新核验。用户只想补一个类别时，按这个类别的缺口去凑学分（4+4、5+3 这种组合由现有的凑学分逻辑算）。
6. **顺手修**：前端把 `UNMODELED_CURRICULUM_RULES` 映射错成了 `UNMODELED_RULE`；在读课程逐门列出；每条"无法确认"都写明下一步该做什么；演示账号导入后勾选"记录已完整"。
7. **页面标注**：演示环境顶部固定显示"课表为模拟数据"。

## 需要确认

- 通选课要不要也模拟一批（比如 20 门，2～4 学分）？不模拟的话，"推荐加通选课"就没有课可推，只能显示还差多少分。
- 模拟班次用真实老师的名字（这样能和真实评价对上），还是用虚构的名字？用真名效果最好，但这份数据只能在演示环境里用，不进公开仓库。
- 什么时候演示，决定要做到哪一步。

**方案调整**：本学期的班次改用真实课表，模拟数据只留作备用。按规则，真实数据导入后仍然是"未核验"，要做两件事：

1. 合同里 `sourceKind` 现在只有 BROWSER_SNAPSHOT 和 SYNTHETIC 两个值，PDF 来源套哪个都不对，需要新增一个值（例如 `OFFICIAL_DOCUMENT`）。这是接口变更，Schema、Java、Python、网页、TRD 要一起改。
2. 增加人工核验步骤：由**上传者以外的一名队友**对照原 PDF 抽查（比如 50 条），记下核验人、抽查数量、差错数，通过后由管理员把快照标成 VERIFIED，并留审计记录。没核验之前，核验结论照实显示"班次来源尚未核验"。

评价按"课程名 + 老师名"匹配，匹配不上的就显示"暂无评价"，不硬凑。
