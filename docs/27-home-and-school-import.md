## `/setup` 配置（三步，可以退回上一步）

### 第 1 步 · 装插件

给安装说明和下载位置（`browser-adapter/academic-progress/`）。
页面能自己判断装没装：往 window 发一次 `CP_START_IMPORT`，
有 `CP_IMPORT_READY` 回来就是装了。

### 第 2 步 · 登录正方教务

一个按钮，在新标签打开学校的学业情况页面。

**学生自己在那个页面上登录。** 我不代登录、不碰学校密码、不存 cookie。
插件只在学生已经登录的页面上读已经渲染出来的文字。

### 第 3 步 · 导入

点一下，插件把页面上的内容送回来，经网关写进 Java。
导完显示导到了什么（几门课、什么时候导的），不显示「成功」两个字就完事。

### 这一步要说清楚：导入的是「你学过什么」

| | 从哪来 | 现状 |
|---|---|---|
| 你学过哪些课、过没过 | 插件读学业情况页面 | ✅ 这一步导的就是它 |
| 学校开设哪些课（培养方案 95 门） | 培养方案表格，已经导好了 | ✅ 不用学生再导 |
| 这学期谁上、周几第几节 | 选课系统，选课开放才公开 | ❌ 现在拿不到 |

所以第 3 步的文案不能写「导入课程内容」——容易让人以为课程库也要自己导。
写「导入我的学业记录」。

## `/me` 个人控制台

四块，一屏之内：

**① 我的状态** — 专业、已修多少学分、还差多少（来自 Java 学业核对）。
数据来源的 `sourceValidation` 原样显示，`UNVERIFIED` 就写 `UNVERIFIED`。

**② 问 AI** — 一个对话框，底下给几个能点的问题：
「我学了什么」「我还能学什么」「这个方向需要学什么」。
走现有网关的会话接口，预算和证据链不变。
回答里引用到的课程和评价要能点开。

**③ 看开什么课** — 真实培养方案 95 门，按类别分组（5 类）。
39 门有真实评价的标出评价条数和维度标签；另外 56 门写「暂无评价记录」。
不算分数不给星级。
点一门课展开：学分、建议学期、评价原文摘录、历史出现过的教师名。
「这学期谁上课」写「未知，选课开放后才公开」。

**④ 开始选课** — 按钮，进现有的 `/plan/questions/goals`。
前置条件没满足（没有核对结果）就直接链回 `/setup`。

## 要加一个接口

③ 要显示每门课的评价条数，现在只能一门一门调 `/api/v1/reviews/search`，
95 门 95 次请求。

`GET /api/v1/review-summaries?curriculumSnapshotId=&limit=&cursor=`
→ 每门课的 `courseCode` / `noteCount` / `dimensions` / `teacherDisplayNames`。
**只给计数和标签，不给分数。** Java 组装，网关转发，网页只展示。
草稿在 `contracts/proposals/review-summary.md`。

---

## 一个之前没说清的结构事实

`/api/v1/teacher-course-options` 对真实培养方案返回 **0 条**。
因为教师选项是从开课班次组装的（`TeacherReviewAssembler`），班次为 0。

**教师挂在班次上。** 选课没开 → 没班次 → 没有「这学期谁上」。
历史教师名只能从评价记录里带出来，覆盖 39 门。
