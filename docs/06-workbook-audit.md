# 2024 级教学计划 `.xls` 数据核查

来源：用户提供的 `以此为准，计算机2024级教学计划表20250306.xls`；本地副本放在 `data/raw/`，被 `.gitignore` 排除。SHA-256：`3c405feaa6d73bd067b1c03df6abd635b7b987bfe1d35ae6971363ab7bb7a756`。本页是对文件内容的只读检查，不是已完成的 Java 导入结果。

## 文件实际结构

共有 **24 个工作表**，覆盖计算机科学与技术、智能科学与技术、网络空间安全、人工智能的直招/非直招版本，各 3 张表。计算机科学与技术非直招用 `计科学1`、`计科学2`、`计科3`；直招用 `计科学直招1/2/3`。第三张表命名不完全一致，解析时必须建立显式 sheet 映射，不能用“前缀 + 3”拼名字。演示版本需在第 1 周由团队选定，不能把不同培养路径混算。

| 表型 | 实际字段例子 | 解析注意 |
| --- | --- | --- |
| 表 1 | 分类、课程编号、名称、学分、建议学期、文字规则 | 多级分类和合并单元格；`计科学1!F45` 为专业选修 24 学分，`F48` 显示总计 257；`F6` 的 `8+4` 不是单一小数 |
| 表 2 | 两组左右并列的课程编号、名称、学分、学期和备注 | 左组代码/名称/学分约在 A/B/C 列，右组约在 N/O/P 列；重复表头不能当课程；`计科学2!N7` 有 `08305011~012` 这种组合编号 |
| 表 3 | 实践环节编号、名称、周数、学分、形式、学期、备注 | 和理论课程结构不同；`计科3` 底部注释含三选一规则，不能只靠数值列自动推断 |

`计科学1` 第 49 行有通识课与线性代数的学期限制，第 53 行要求毕业前至少一门全英语授课课程；`计科学2` 第 19 行提示第 9 学期及之后的专业选修可能调整。这些文本规则需人工转成 `Requirement`，记录工作表、行、原文和审核者；未确认时返回 `UNKNOWN`。

## 能做与不能做

这份文件可作为**培养要求、课程目录、建议修读学期**的来源。它**没有具体班次的星期、节次、教室、任课教师、实时开课或余量**，因此不能仅凭此文件判定“周五空出来”或两班次不冲突。若没有额外的当学期班次快照，界面只能给出“建议修读课程”，时间冲突、课表优化一律标未知/不提供。

## Java 导入验收办法

1. 用 Apache POI `WorkbookFactory` 读取 `.xls`；`DataFormatter` 保留课程号前导零，不把 `00944008` 变成 `944008`。
2. 明确 `major + track + sheetName + row + column` 的来源键。先实现一个确认过的计算机科学与技术路径，其他路径标未审核。
3. 对表 1、左右并列表 2、实践表 3 分别写解析器；跳过重复表头/小计/注释行，将未知文字规则单列为 ImportIssue，阻断自动发布；受控模板规则需有黄金样例。
4. 对组合编号、`8+4`、`详见附表`、三选一、缺失学分做异常清单，不自动拆解或猜测。
5. 手工抽查每种表型至少 5 行，核对课程号、学分和来源位置；对 `计科学1!F45/F48` 等关键值做独立总量校验。
6. 入库记录文件 SHA、选择的路径和导入时间；同 SHA 重导幂等，新文件生成新 `curriculumSnapshotId`，旧评测不随之漂移。

## 与班次来源的关系

本页结论仅针对 `.xls`：它没有班次时间。用户本机另有 `选课插件v0.6.js`，其代码可观察上大选课页的班次响应，因而**班次入口已有可验证线索**，并非来源完全未知；但 CoursePilot 尚未接入，也未在本人页面验证字段与稳定性。目前无法进入选课页实测，[浏览器适配设计](09-browser-adapter.md)仅为静态推断。首版用 `SYNTHETIC` fixture 测冲突算法；真实请求仍返回 `OFFERING_UNAVAILABLE`。SQL/规则落地见[实施方案](10-java-import-and-rules.md)。
