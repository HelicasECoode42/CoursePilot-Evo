## 1. 给队友的阅读顺序

1. 先打开 [HTML 示例](../demo/coursepilot-guided-demo.html)，体验一次一问、不同选课动机、课程教师选择与评价详情。
2. 读 [HTML 交接规范](../demo/README.md)，理解交互和占位边界。界面风格和行为以此为参考，不把演示 JS 当生产业务逻辑。
3. 读本文件，明确产品基线、每批交付和自己负责的范围。
4. 按模块读 [统一契约](04-infrastructure-workflow.md)、[总体 TRD](03-trd.md)及 [A–E 子 TRD](05-team-and-sub-trds.md)。
5. 需要选课维度与公开资料依据时，查 [需求研究](14-student-choice-research-and-ux.md)。

本文件负责交付顺序；PRD 负责产品需求；统一契约负责字段与接口；子 TRD 负责具体做法。接口字段以统一契约为准。W1 冻结后，变更必须同步相关 DTO 和 fixture。

## 3. 五周必须守住的主线

一个已经核对的计算机培养路径 → 导入或载入虚构/授权的已修记录 → 自动学业核对 → 按目标一次一问 → 课程和教师评价比较 → Agent 提候选 → Java 二次验证 → 学生调整与 replan。

当前没有可验证的真实班次，实际使用只能做课程层面的规划、保存教师意愿与时间未知提示。另设显著标记为模拟的演示数据，验证时间解析、冲突和 replan。不得将这条算法演示当成真实课表。

RSI 是第二条必需的实验交付：同一 Runner 跑四组基线，跨多个 Trace 找重复失败，产生有限 patch，经隔离 held-out 判决，至少运行两轮候选决策。质量提高和省 token 都是待验证目标。评测设计 W1 开始，不能等页面全部完成才开始标注。

五周范围不扩张：首个培养路径、有限评价样例、少量有来源的职业介绍、匿名本地演示。实时 BOSS/评价爬取、学校登录、自动选课、全校多专业培养核对与成绩预测不进入首版交付。HTML 的其他学科选项展示扩展交互，不代表支持其培养计划。

## 4. 统一对象与所有权先定下来

| 共享对象/规则 | 提供者 | 消费者 | 第一批要冻结的内容 |
| --- | --- | --- | --- |
| CurriculumSnapshot / Course / Requirement | A 导入，B 存储 | B/C/D/E | 培养路径、课程号、学分、规则、来源与发布状态 |
| CompletedCourse / academicRecordRef | A 导入格式，B 存储核对 | C/E | 完整性、通过/重修状态、版本；不能隐式获取成绩 |
| AuditResult | B | C/E/D | 未完成要求、类别缺口、建议修读、unknowns 分开 |
| CourseOffering / Meeting | A 提供原始字段 fixture；B 维护唯一时间解析器 | B/C/D/E | term/classId/teacher、原始时间、结构化周次、parseStatus |
| ReviewNote / evidence refs | A 整理/导入，B 查询 | C/E/D | 课程×教师×修读学期、评价维度、来源、新鲜度与匹配状态 |
| GoalIntent / PlanningRequest | C 与 E 共同定，C 校验 | C/B/D/E | 多动机、优先级、hard/soft、指定课程教师、未知项 |
| PlanningAnswer / verifierResultId | C 组织，B 提供核验 | E/D | 事实、建议、证据、未知、澄清与可重规划引用 |
| Trace / run manifest / lineage | C 发事件，D 定规范与存档 | D；E 的独立报告页 | 模型/预算/快照/API/Harness 版本和 token/tool/latency |

时间文本不由 A、B、C 各写一个解析器。B 维护唯一 Java TimeParser 和 ConflictChecker；A 提供原文、映射与黄金输入，规范化时调用共用解析器。C/E 只读解析与校验结果，不能自行用自然语言推断时间。

接口冻结是最小可集成合同，不是要求 W1 写完所有功能。用一条学业核对、一条无班次 UNKNOWN、一条带评价候选、一条模拟冲突 fixture 先让五人同时开发。

## 5. 分批交付与门槛

### 第 0 批：共同合同与演示基线（W1 前半）

- 全组读 HTML 和交接规范，确认问题路由、动机与数据边界。
- A/B 选定一个培养路径，冻结课程/要求/已修/来源对象和导入异常。
- B/C/E 冻结查询、核对、规划答复和错误封套；C/D 冻结 Trace 与 Runner 入口。
- D 同时给四组各两条种子 case，其中包含建议学期误判、教师评价混淆、时间 UNKNOWN。
- E 将 HTML 拆成 Vue 问题页、记录入口、详情层、候选页，先用共享 fixture。

门槛：相同 fixture 可以被 Java/Python/Web 接收；样例中真实/模拟/未知三种状态明确；个人模块不再另造对象。交付：契约、fixture、首批 case 和每人具体任务。

### 第 1 批：数据库与学业事实（W1 后半至 W2）

- A 完成选定路径的 POI 导入、来源定位、重复导入和异常阻断；整理少量评价输入。
- B 建 Flyway 表和只读查询，完成学业核对；建议修读与未完成必修分别返回。
- E 做学业记录展示、缺记录导入入口与状态；正常使用不重复输入已修课。
- C 用固定 Tool 返回实现意图提取与有限工具调用；D 核对 case 答案来源。

门槛：课程/学分和原表基线一致；未知文字规则不发布；不完整已修记录不能给确定缺口；导入可重复。真实班次未接入不阻塞培养核对。

### 第 2 批：最小学生闭环（W2 至 W3 前半）

- E 实现一次一问、多动机与返回保留答案，按选择跳过无关职业题。
- C 汇总结构化意图，查询 B，提出候选并调用验证；缺关键证据时澄清或停在课程层。
- B 交唯一时间解析器、模拟冲突检查和 UNKNOWN 返回。
- A 交单双周/离散周/未知格式黄金 fixture；D 用同一 Runner 采集 Trace。

门槛：Web→Python→Java 一条链贯通；缺班次时不能绿色显示“无冲突”；正常建议与错误/未知分别显示。不能以播放预写结果代替已实现的 Agent。

### 第 3 批：课程教师与取舍（W3 后半）

- A/B 完成有限评价导入和按课程×教师×学期查询，保留样本、年份与分歧。
- E 加教师课程搜索、意愿绑定、评价详情；已有 HTML 提供行为参考。
- C 区分必须保留/优先考虑；指定教师与硬时间冲突时问取舍，不静默换教师。
- C/E 完成少量计算机岗位介绍内容；其他学科保持扩展占位。
- D 增加少签到不等于少作业、好评不等于高分、旧评价不证明当期开课等 case。

门槛：每条评价摘要能追溯原记录；没有证据显示未知；修改一个条件可 replan；多动机没有互相覆盖。W3 结束冻结首版产品范围。

### 第 4 批：基线与失败归因（W4）

- D 完成四组 evolution/held-out 隔离任务，优先目标每组 5+5；标注不足时按既定最低 3+3 如实缩放。
- C 固定模型、温度、预算、API 与 Runner；保存实际 token、调用与耗时。
- B/D 复核事实标签和 Java 核验；evaluator 不以模型答案反推真值。
- D 从至少两个不同 case 的 Trace 建 failure hypothesis，C 协助解释可修改策略。
- E 在独立老师报告页显示基线质量、成本、失败类型，不进入学生问题流程。

门槛：能够重放 v0、看到逐例结果；Evolver 没有答案/held-out/评分器访问权；假设有跨 case 证据。W4 结束冻结评测条件。

### 第 5 批：双轮候选与验收（W5）

- D 运行两轮候选：稳定版本→patch→隔离评测→晋级/回滚→再从稳定版本继续。
- C 负责 Harness 装载与有界运行，A/B 处理暴露的事实错误；改数据/API 后必须重新建立可比基线。
- E 准备学生闭环演示与老师演化报告，成功与 UNKNOWN/失败都要能展示。
- 全组核对实现清单、限制、测试证据和演示说明。

门槛：有两次候选决策及 lineage；未晋级就报告 rejected，不强行写 v1/v2 成功。省 token 只能用固定条件下实测报告，质量不能因减少证据而退化。

合计 55 人日约 330–440 小时，按每人日 6–8 小时估算，未含个人学习速度差异。每周留出集成和返工，不按五个人全职五周承诺。

## 7. 谁先交给谁

- A→B：规范化输入、来源、异常与 golden fixture；不是网页原始 DOM。
- B→C/E：JSON 封套、Audit、候选课程教师、评价证据、核验结果；不让前端重算学分。
- C↔E：问题答案→同一 PlanningRequest；PlanningAnswer→当前问题/候选/未知提示。
- C→D：唯一 Runner、冻结配置和脱敏 Trace；D 不写评测专用 Agent。
- D→E：报告 DTO 和 lineage，仅供独立老师页；学生页面不展示工程术语。

W1/W2 每人先交一条可调用的最小纵向切片；每周一起跑普通建议、资料缺失、冲突/取舍三个场景。接口变化写清字段、版本和影响者，再同步 fixture；不要只在个人代码中偷偷修改。

## 8. 共用完成标准

任务完成必须说明：具体实现、输入输出、测试证据、当前限制。HTML 占位不算服务完成；fixture 不算真实学校接入；手动改 Prompt 不算 RSI。

学生主线验收：无需重复手填已有关联记录；问题按动机分支；多目标可修改；课程教师能精确指定；评价有来源与年份；缺数据不编造；硬事实经 Java 校验；无法核验时间不宣布无冲突。

实验主线验收：四组、固定条件、隔离答案/held-out、跨 case 假设、有限 patch、两个候选决策、质量与成本指标、完整失败记录。

真实班次仍不可得时，项目可以交付真实培养规则核对、课程层建议、有限评价参考、明确模拟的冲突算法演示和 RSI 实验；说明这条边界，不编造完整的当期排课能力。
