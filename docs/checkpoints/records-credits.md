# 学业资料与学分选课页面

## 修改范围

修改 `/records` 与 `/plan/credits`。共享学校进度组件增加可选课程明细输入；未传入课程时保持其他页面原有行为。App 仅为学分选课路径启用已有宽页面容器。未修改推荐结果、兴趣引导、教师页面、后端接口或模型配置。

学业资料按 nodeId、parentId 展示学校类别，展开显示绑定课程的名称、编号、学分与修读状态。学校要求、已获、剩余学分保留原值，不累加父子节点。手动补录和本地核对详情默认收起，提供前往学分选课的操作。

学分选课一次查看一个培养要求类别。已选课程跨类别保留，以唯一课程号计算课程数与已知学分，可逐门移除；桌面侧栏、手机底部汇总持续显示。已通过课程从候选中排除，包含课程目录中重复出现的同一课程号。未知学分和未知缺口不当作零。

学校类别与培养方案类别唯一同名时仅展示学校报告参考；多个同名节点不合并。组合算法继续使用本地核对缺口，不修改 Java 的 UNKNOWN。学校报告剩余学分与本地核对结论分别展示。

## 接口与用户画像

接口矩阵、会话草稿与长期画像区别、AI 对话的确认操作和规则职责，见 [学生页面与数据流转](../27-student-experience-and-data-flow.md)。本轮没有新增聊天或长期画像服务。Runner 尚未直接读取学校进度树；其课程状态筛选与学分页的差异已单独记录。

## 检查与恢复

实现前 checkpoint：`a853e7c55b0b9223cd1398d9cd698354d9f8236a`，引用 `refs/checkpoints/coursepilot/20261030T084906797945Z-records-credits-before`。

第一版受影响测试 39 项、lint、类型检查、构建通过。浏览器进一步发现新标签页直接进入导入链接时没有建立会话，现已修复：两页准备会话后再读取资料，失败提供重试，已有 ready 记录不重复读取。直接进入资料页时导入按钮先禁用，准备完成后启用；直接进入学分页而无记录时显示导入入口。浏览器已确认这两条路径。

复核中发现 `loadRecords()` 会无条件清除已有 audit，因此两页初始化仅在记录未 ready 时读取，避免导航清空核对和方案交接。已有核对继续显示的测试断言同时确认不调用该方法。独立复核已确认修复。

主 Agent 最终 lint、类型检查、构建均通过；契约检查通过 3 份 Schema/OpenAPI、本地引用和 22 个正反例。学校节点和课程绑定、类别切换选择保持、课程去重与移除由组件与页面测试验证；本轮浏览器未重新导入学生的真实学业资料，未执行模型调用。

最终 `npm run test:unit` 通过：34 文件、420 项 Web 测试，26 项独立 HTML 测试，两份 HTML 结构检查。

独立审查确认已修课程排除、跨类别选择去重、学校与本地缺口分开。另记录一项既有输入校验不足：后端拒绝自指向父节点，但没有拒绝多节点组成的循环层级，递归组件不能展示这类无根节点。未在实际学校 DOM 导出中发现此结构，本轮没有扩展导入格式规则或增加异常结构处理。

恢复先在独立 worktree 对照 checkpoint，不对当前协作目录执行强制重置。checkpoint 不包含 H2、私有学校资料、密钥或运行中的会话。
