# AI 对话到规划验收

日期：2026-10-30。三名 Luna 分别负责对话后端、前端、候选规则，另一名 Luna 独立审查；主 Agent 维护契约行为文档、执行最终回归和真实服务验收。

## 实现

- 新增 `POST /api/v1/advice/chat`，使用现有会话鉴权、幂等存储、ToolClient、模型适配器与累计用量账本。每轮最多一次模型调用，不自动付费重试；共享 HTTP 传输单次最多 30 秒并受剩余 deadline 限制。
- 对话从当前培养方案、匹配的学校进度及学业记录取得事实，课程名、学分和评价由服务端补全。学校原始成绩不进入模型消息。已查无记录、尚未查询、查询不完整分别返回。
- 统一默认候选为专业选修课和高年级研讨课，排除已通过、在读与编号歧义课程，状态未知保留说明。公共基础退出主动推荐；明确选择的其他类别仍按原有约束处理。
- 正式 Runner 复用学校进度中匹配的学业记录，保留原 audit UNKNOWN。在匹配的导入路径下，学校进度、评价和 Java 核验保持在总计 6 次工具预算内。
- 我的学业中新增真实聊天、课程卡片与采用动作。确认兴趣更新文本；明确选课进入现有选课列表；优先考虑独立保存并转换为 `course.prefer` 软偏好。采用前排除当前记录中已通过或在读课程，重复采用不重复写入。
- 原有完整引导保留；聊天和确认结果在当前会话页面切换中保留。已有记录和方案不因返回聊天重复加载而清空。尚未实现跨会话长期画像或历史对话恢复。

字段与行为见 [对话接口](../29-advice-chat-contract.md)和[公共契约](../04-infrastructure-workflow.md)。

## 真实服务证据

使用 Java 8081 的真实培养文件课程，来源保持 `CURRICULUM_FILE / UNVERIFIED`。测试会话没有导入学生个人成绩；正式规划使用独立测试会话的空记录，并明确 `transcriptComplete=false`，不编造通过课程或缺口。

1. 真实模型对话返回 HTTP 200，推荐 Java程序设计(实践) `08306099`，类别为专业选修，返回兴趣确认与加入待选动作。评价未查询时说明无法据此判断给分与考勤。
2. 同一对话请求和幂等键重放，HTTP 200，完整响应相同，不新增模型调用。
3. 将采用的兴趣和课程构造成现有正式规划请求，真实模型返回 HTTP 200、`RECOMMENDATIONS`；方案保留 `08306099`。Java 核验为 UNKNOWN，原有未建模规则、班次来源和记录完整性原因继续保留。
4. 浏览器另发一次真实问题，点击采用兴趣和课程；页面显示已确认兴趣及课程名。继续原有引导，兴趣步骤保留“后端开发”；返回我的学业仍有消息和已选课程。
5. 390px 窄屏检查中，聊天页面文档宽度和滚动宽度均为 390px。保存桌面及手机截图供核对。

本轮共执行 3 次真实模型调用：一次 API 对话、一次 API 正式规划、一次网页对话。API 对话用量 input 2720、output 1131，耗时 8429ms；API 规划 input 2833、output 1714，耗时 11998ms。网页调用未另导出 token 统计，不把这两次用量相加描述为本轮总量。后续提示词中文表述和 30 秒超时调整使用受控测试验证，未为其增加付费调用。

学校进度进入模型、已修排除和跨记录隔离由受控测试验证；本轮没有重新进行学生真实学校页面导入对照，也未验收真实下学期课表。上述证据不构成模型可靠性成功率评测。
